# fanout

**대화에서 정리한 「고칠 것들」을 하위 세션에 나눠 맡기고, PR 병합과 정리까지 끝내는 Claude Code 플러그인**

Claude 데스크톱 앱(Code 탭)에서 메인 세션 하나로 진단·검토를 하다 보면 고칠 것이 여럿 쌓입니다. `/fanout`을 부르면 이 목록을 서로 같은 파일을 건드리지 않게 묶어 하위 세션으로 띄웁니다. 각 하위 세션은 설계·계획 검토부터 PR 병합까지 혼자 끝냅니다. 모든 세션이 끝나면 메인 세션이 합쳐진 상태를 다시 검증하고, 하위 세션과 워크트리를 정리합니다.

## 흐름

```
메인 세션 ─ 나누기 ─ 사용량 확인 ─┬─ 하위 세션 1: 설계·계획 검토 → Codex 구현 → Opus 검토 → cascade-fix 수정 → PR 병합
                                ├─ 하위 세션 2: …
                                └─ (2단계: 1단계 결과가 필요한 항목은 1단계 병합 뒤에 띄움)
          ← 통합 검증 → 하위 세션 보관·워크트리·브랜치 정리 → 최종 보고
```

1. **나누기** — 같은 파일을 건드리는 항목은 한 세션으로, 한두 줄짜리는 「잔여 수정」 세션으로 묶습니다. 다른 항목의 결과가 필요한 것은 2단계로 미룹니다.
2. **사용량 확인** — 띄우기 전에 데스크톱 앱이 보여 주는 플랜 한도(5시간·주간·모델별 주간, 추가 사용량)를 읽습니다. 80%(추가 사용량은 90%)를 넘으면 「기다리기 / 줄여서 진행 / 그대로 진행」 중 하나를 고르게 합니다. 그보다 낮으면 한 줄만 보여 주고 묻지 않습니다.
3. **하위 세션** — 세션마다 별도 워크트리에서 돌고, 메인 세션 대화를 모르므로 근거(파일:행, 커밋)를 brief에 직접 담아 넘깁니다.
4. **통합 검증·정리** — PR 병합을 `gh`로 확인하고 합쳐진 기본 브랜치에서 저장소 검사를 다시 돌린 뒤, 하위 세션을 보관하고 남은 워크트리·브랜치·임시 파일을 지웁니다.

`/fanout`을 부른 것을 하위 세션 시작, Codex·Cursor 전송, PR 병합, 정리에 대한 승인으로 봅니다. 사용량이 임계값을 넘었을 때만 다시 묻습니다.

## 병합 제한 저장소

전역·프로젝트 `CLAUDE.md`가 병합·배포 원칙(직접 병합 금지, PR base 브랜치, 승인자 등)을 정해 둔 저장소에서는 그 원칙이 우선합니다. 이때는 하위 세션도 메인 세션도 PR까지만 만들고, 병합·태그·배포는 사람이 합니다. `/fanout`의 인자로도 이 예외는 풀리지 않습니다.

## 필요한 것

- **Claude 데스크톱 앱의 Code 탭** — 하위 세션 띄우기·보관, 사용량 읽기에 앱 전용 도구를 씁니다. 터미널의 `claude`에서는 동작하지 않습니다.
- **플러그인:** [superpowers](https://github.com/obra/superpowers)(brainstorming·writing-plans), [cascade-fix](https://github.com/sch0718/cascade-fix)
- **Codex CLI** — 구현을 맡깁니다(`codex exec`).
- **`codex-review` 스킬** — 설계·계획 문서 검토에 씁니다. 이 저장소에는 들어 있지 않습니다. 없으면 brief의 해당 줄을 쓰는 리뷰 방식으로 바꿔 주세요.
- 로그인된 `gh` CLI, git

## 설치

Claude Code 세션에서:

```
/plugin marketplace add sch0718/fanout
/plugin install fanout@sch0718-fanout
```

터미널에서는 `claude plugin marketplace add sch0718/fanout` 뒤 `claude plugin install fanout@sch0718-fanout`입니다. 새 버전은 다음 세션부터(또는 `/reload-plugins` 뒤) 적용됩니다.

## 사용 예시

메인 세션에서 고칠 것 목록이 정리된 뒤에 부릅니다.

```
/fanout:fanout
/fanout:fanout 3번 빼고
/fanout:fanout 병합은 하지 말고 PR까지만
```

「고쳐야 하는 것들 하위 세션에서 진행해줘」, 「나눠서 병렬로 진행하고 병합까지」처럼 말로 맡겨도 됩니다. 한두 줄짜리 수정 하나뿐이면 쓰지 않고 메인 세션에서 바로 고칩니다.
